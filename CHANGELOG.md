# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

## [0.5.0] - 2026-09-12

Phase B recall and correctness across the JVM, Swift, Objective-C, PHP and .NET wrappers, plus two new signals the host can act on: every sidecar can now report a `PluginDiagnostic` on `InvokeResponse.diagnostics`, and the Swift and Dart emitters answer `--version` so a stale emitter is visible instead of silently producing results that do not reflect the source. Several wrappers changed which build phase they drive (Maven `test-compile`, sbt `Test/compile`, SemanticDB in every sbt scope), so test-scope references enter the graph for the first time on those languages.

Minor rather than patch: the sidecars now require a `travsr-core` that carries `InvokeResponse.diagnostics`, and the emitter version handshake means a Swift or Dart emitter from an earlier tag reports a skew against this one. Rebuild and reinstall both emitters when you upgrade.

### Added

- Swift, Dart: a version handshake between each sidecar and the emitter it spawns. `cargo build --release` at the repo root does not build either emitter, so a developer who rebuilds the workspace gets a new spawner talking to whatever binary is already in `~/.travsr/bin`, and a stale emitter emits well-formed output whose only symptom is results that quietly do not reflect the source. Each sidecar now asks its emitter for `--version` and warns when the emitter does not understand the flag (so it predates the handshake) or reports a different version than the sidecar's own package version. Both signals are WARN and never fatal, since a skewed emitter still produces a usable index. The verdict is cached per emitter path and build time, so an in-place rebuild is probed again rather than reporting a fixed skew forever, and a repeat invoke still gets the diagnostic to attach to its own response. The Dart emitter gains the `--version` flag it was being asked for, and CI fails the build when the three emitter version literals disagree with the Cargo workspace version.
- The occurrence column (`caller_col`) is now populated rather than left `None` everywhere (#813). PR #26 added the field and deferred filling it. Two rules, split by whether we own the producer: an emitter we own declares its unit (`col_unit: "utf8"` from Swift, `col_unit: "utf16"` from Dart) and the consumer converts, so a future toolchain change is a change to that value rather than a silent skew; a producer we do not own declares nothing reliable, so the column is kept only while the line prefix is pure ASCII, the window inside which one code unit is one byte under all four SCIP encodings. Measured over the 39,555 committed occurrences of the travsr repository, 99.985% fall inside it. Outside it the column is left unset and the daemon name-searches the line exactly as before, so there is no regression. scip-reader stops discarding range element `[1]` (covering c, cpp, csharp, go, java, objc, php, python, ruby), kotlin reads `range.start.character`, scala parses SemanticDB `Range` field 2, and `SourceCache` is shared so every language applies the same predicate rather than four reimplementations of it.
- A diagnostic channel. Every sidecar that builds an `InvokeResponse` now names the `diagnostics` field added on the travsr side, and three conditions report through it instead of a log line nothing reads: an emitter version skew, a test-blind semantic index, and a Scala build root outside the host's write grants (`scala.build-root-not-granted`, naming both paths). The host only echoes sidecar stderr when a run yields zero nodes, and each of these produces a populated but partial index, which is exactly the case that echo could never cover.
- Java, scip-reader: a test-blind semantic index is reported as a diagnostic. A Phase B analyzer driven by the project's own build indexes only what the build compiles, so when the build skips the test scope the analyzer still exits 0 and still emits a valid index with the scope simply absent. Nothing downstream could tell that from a repo whose tests genuinely make no calls, and `travsr lang list` kept reporting the language healthy while a large share of the corpus was semantically dark. `warn_if_test_scope_dark` detects it from the daemon's pre-walked file list and attaches the finding to `resp.diagnostics`; the check is generic and Java passes its own cause hint naming the build flags that produce the condition for its ecosystem.
- A unit test target for the Swift emitter (`swift test` in `packages/swift-index-emitter`), pinning the symbol resolution rules rather than a reference count that does not move when a resolution change retargets a symbol, and CI jobs that build and smoke-test the emitter on both macOS and Linux. The emitter is not built by cargo, so nothing in CI noticed when its output changed or stopped compiling. README documents the manual build and install steps the automation mirrors.

### Changed

- Java: the Maven driver asks for `test-compile` instead of the project's default lifecycle. scip-java's default runs the full lifecycle, which is both more than SemanticDB needs and more than most repos survive during indexing: on the pinned JSON-java fixture it reached maven-gpg-plugin and died with `Cannot run program "gpg"`, so Phase B produced nothing. The workaround for that had been `-Dmaven.test.skip=true`, which is worse, because SemanticDB is a javac plugin and a test source the build never compiles produces no index, so not one call site in any test file reached the graph. `test-compile` is the earliest phase that compiles both source roots and runs no tests, javadoc, signing or deploy. Measured on that fixture: default lifecycle 0 ref/call, `test-compile` 3,881 ref/call with 2,883 of them originating in `src/test`, and `references numberToString` goes from 2 refs in 2 files to 9 in 3, the full hand-audited caller set. Scoped to Maven on macOS and Linux; Gradle keeps scip-java's default and Windows routes to `run_windows`, which refuses Maven.
- Scala: the wrapper asks sbt for `Test/compile`, falling back to plain `compile` when the project has no test configuration, so test call sites are no longer invisible.
- Kotlin: indexing waits on the server's own progress signal instead of a blind 180s timer. The wrapper parked `window/workDoneProgress/create` unanswered, so KLS's progress future never completed, no `$/progress` was ever emitted, and `SymbolIndex.refresh` (which runs inside that same continuation) never built the dependency index either. The wait also ran before any document was open, where the lint debouncer has nothing to do. The wrapper now answers server-to-client requests, declines anything else with `MethodNotFound` rather than silence, moves the wait after the `didOpen` pass, replays the inbox before blocking, and requires the token from `window/workDoneProgress/create` in both progress predicates so a configuring or lint reporter closing first cannot declare the server ready. Fifteen consecutive fresh indexes are byte-identical (2,157 nodes, 3,256 edges, 2,076 ref/call, compared as sets), and wall clock drops from 213 to 227s down to 43 to 52s. If the signal were ever missed the pre-existing timeout still applies, so the worst case is the old behaviour.
- Kotlin: the Maven fallback is removed. It fired on any error including a timeout and re-ran the project's default lifecycle, which is what driving `test-compile` exists to avoid: arbitrary test code, gpg, deploy, inside the sandbox on repo-controlled build config. It is also a strict superset of `test-compile`, so it cannot pass where `test-compile` failed on test sources. The `kotlin.index-incomplete` diagnostic is dropped as well, since a timeout means the progress signal was not observed rather than that the index is incomplete, and its suggested remedy could only lower the wait.
- PHP: scip-php is invoked from the repo root with only the arguments it defines, rather than from a directory where it cannot find `composer.json` and with flags it does not accept. Its stdout is drained while it runs, so a chatty run no longer blocks on a full pipe.
- Scala: the two sbt attempts share one deadline instead of a `180 + 60` split sized as though both budgets were spent back to back. The split cost real indexes at both ends: a cold coursier resolve needing 180 to 300s used to complete under the host's own 300s ceiling and now failed at 180, while a fast failure at 20s left the fallback 60s of a window with 200s free, and a non-zero exit at 170s followed by a full fallback could overrun the host and be SIGKILLed with the diagnostic still unsent. The reserve for the SemanticDB scan, the parse and the host reply margin is now named rather than implied, and a retry with too little left to reload the build is skipped with a reason. Constants mirror the Kotlin sidecar, which already solved this.
- CI pins every third-party action to a commit SHA and adds a least-privilege `permissions` block.
- The Dart emitter source shipped inside `@travsr-plugin/dart` (`share/travsr-lang-dart/`) is resynced with `packages/dart-scip-emitter`, from which it had drifted by the column and `--version` work.

### Fixed

- Scala: a multi-module or sbt-crossproject build produced zero `.semanticdb` files. The wrapper wrote a root-scoped `semanticdb.sbt` and then looked only under `<root>/target/`, so sub-projects never had SemanticDB enabled and their own `target/` output was never read; a warm standalone `sbt compile` also left Zinc with nothing to recompile, so the sidecar returned in seconds having produced nothing, and the stdout that would have shown this was drained and discarded (travsr#832). The `scalacOptions` are now set from the command line with `set every semanticdbEnabled := true`, which reaches every sub-project (including sbt-crossproject JVM/JS/Native targets) and forces a recompile, the walk collects `.semanticdb` from every sub-project's `target/` at any depth while skipping dot-directories so the Metals/Bloop copies of the same sources are not ingested twice, and a compile that succeeds with zero output now logs the bounded sbt stdout/stderr tail at `warn`. Enabling SemanticDB in every scope also covers `Test`, so test-source references now enter the graph.
- Swift: the emitter recorded references only from call sites and member accesses, so a type used purely in type position produced zero references. `let x: WBMDAdManager`, a parameter or return type, a generic argument, and a superclass or protocol conformance were all invisible, so a file that only used a type in annotations yielded a definition-only document and `find_references` on the most-used API types returned a confident zero (travsr#830). The visitor now records a reference for every named type in a type position, recursing through optionals, arrays, dictionaries, tuples, `some`/`any` and generic arguments and skipping the language builtins, and the receiver type of a qualified static access (`Enum.constant`, `Type.method()`) is recorded alongside the member. This mirrors the Dart emitter's type-position capture (#14). Generic parameter names (`Item` in `struct Stack<Item>`) are tracked and skipped so they cannot resolve to an unrelated type of the same name, while their constraints (`<T: Proto>`) are recorded; `extension Foo: Proto {}` now records both the extended type and the conformance; and a closure parameter named `_` records its type like a function parameter already did. The CI smoke test now asserts a type-position reference is emitted.
- Swift: type-position references would have entered the call graph. The emitter's `Reference` had no call/non-call signal and the Rust wrapper hardcoded `is_call: true`, which `travsr-store::write_scip_attributed_batch` turns into a `ref/call` edge, so `let x: WBMDAdManager`, `func makeA() -> ClassA` and every generic argument would have made `get_callers` and blast radius report each declaration site as a caller. The emitter now writes `"is_call": false` on type-position uses and on the receiver type of a qualified access, and the wrapper reads it. The key is written only when false, so JSON from an emitter built before this keeps today's behaviour.
- Swift: a generic parameter used inside an extension leaked as a type reference. An extension does not restate the extended type's parameters, so `extension Stack { func peek() -> Item? }` emitted `swift::Item`, a wrong occurrence for any repo that also defines a type named `Item`, `Element`, `Key`, `Value` and so on. A pre-pass now collects each type's generic parameter and associatedtype names across all files, and the extension visitor brings the extended type's parameters into scope (plus a table for the common standard-library generic types, so `extension Array` does not leak `Element`). Protocols push their associatedtypes for the same reason, so `associatedtype Element; func first() -> Element` no longer references a real `Element`. An associated-type projection (`T.Element`, `Self.Element`) is likewise not recorded as a reference to a real `Element`. The CI smoke test asserts an extension of a generic type does not leak its parameter.
- Swift: type-position capture now reaches function types (`(Foo) -> Bar`), protocol compositions (`Foo & Bar`), metatypes (`Foo.Type`), enum case associated values (`case a(Payload)`), `typealias` right-hand sides, generic `where` clauses and `as` / `is` cast targets, each previously undercounted against ripgrep truth for travsr#830.
- Swift: an uppercase-named local no longer produces a spurious static-type reference. `let Config = ...; Config.count` treated `Config` as a type because the receiver heuristic keyed on the leading capital; the visitor now consults the in-scope local names first, so a local shadows a type of the same name as Swift itself resolves it.
- Swift: an instance method call was attributed only when the receiver's type was written explicitly at its declaration, so `Engine.start` collected 1 caller out of 4 on the common shapes: a stored property receiver (`prop.start()`), an inferred local (`let e = Engine(); e.start()`) and a fresh instance (`Engine().start()`) all produced nothing, while an annotated local, a static call and a `self` call worked. `constructedTypeName` now returns the type a `T()` call yields when `T` is a type the repo declares and is not a generic parameter, an unannotated binding whose initializer is a constructor call binds the local, a call whose base is a constructor call resolves through it, and a bare receiver that is not a local, not a generic parameter and names no type resolves as an implicit-self property. Unresolvable receivers still emit nothing rather than guessing. Purely additive on real corpora, old binary against new: swift-syntax 95,422 to 99,501 references with 0 removed, fastlane 7,176 to 7,198 with 0 removed. Probing this also found a pre-existing wrong edge, where a `guard let` or `for in` binding whose name matched an annotated property resolved to the property's type; `scopeNames` was documented to hold all in-scope locals but only `let`/`var` declarations, parameters and closure parameters ever reached it.
- Swift: a member reached through a base class or a protocol extension is keyed on the type that declares it rather than the type written at the call site, a call on a generic parameter resolves through its constraint, an `X.Type` metatype receiver reduces to `X`, and `self.<property>.method()` resolves through a pre-pass table of each type's property names against their declared types, scoped by enclosing type so `self.foo` in `struct A` cannot pick up `foo` from `struct B`. Measured on swift-argument-parser: 10,092 to 10,096 references, 4 added and 0 removed, all four verified genuine.
- Swift: the emitter's supertype walk seeded its BFS from `Array(Set<String>)`, and Swift's hash seed is per process, so with two protocol default implementations the emitted symbol flipped between runs over the same unmodified repo. `typeParents` keeps declaration order now. `recordMember` also no longer records locals and nested functions as type members.
- Objective-C: `[ClassName selector]` class sends produced no `ref/call` edges while instance sends worked (#831). Two class-specific gaps in the glob-fallback path. The compdb fallback added only `-I<root>`, so a quoted `#import "Foo.h"` whose header sits in a subdirectory never resolved, and an unresolved import leaves the callee class undeclared, at which point clang drops the whole `[Foo bar]` statement from the AST so no cursor walk can see the send; every header-bearing directory is now collected in one tree walk and added as a search path, plus a best-effort `-iframework` for the platform frameworks directory. The visitor's syntactic fallback read the selector from `cursor_spelling` on the message expression, which is empty for an unresolved send, so it never fired; receiver and selector are now recovered lexically from the send's own tokens, gated to a class-cased receiver so instance, `self` and `super` sends stay skipped. Verified on AFNetworking: `references policyWithPinningMode` 0 to 44 callers.
- Objective-C: a translation unit that failed to fully parse cost every reference in the file. libclang still produces a usable AST for it, but the visitor bailed on the whole TU, so a single missing system header was enough. It now walks the tokens it did get and recovers the references it can identify, and declines candidates inside preprocessor conditionals, where a raw token scan cannot tell an active branch from an inactive one. The class-send recovery also iterated a `HashMap`, so emitted reference order varied run to run and two indexes of the same commit could differ; a `BTreeMap` and a sort over the glob-fallback sources make three fresh indexes of the fixture produce an identical edge-set hash. The recovered send's occurrence now ends at the first selector keyword rather than running the length of the whole `setFoo:bar:` selector and crossing into the argument list.
- Scala: the stdlib filter matched on package prefix alone, so it dropped a repo's own definitions whenever the repo is itself a `scala-library` package. On scala-parser-combinators, whose sources live under `scala/util/parsing`, that discarded essentially every definition the compiler produced. It now keeps a symbol the repo itself defines and filters only what it does not.
- C#: `dotnet_root()` only scanned PATH, so a daemon launched with a minimal PATH (no `/opt/homebrew/bin`) left the plugin host unable to find dotnet and nothing was injected, scip-dotnet fell back to the hardcoded `/usr/local/share/dotnet`, and the C# live lane got no reference edges. It now tries a set of launcher locations PATH-first and then the well-known installs a sandboxed PATH omits (Homebrew's version-independent opt symlink on Apple silicon and Intel, the official installer directory, a user-local `~/.dotnet`), mapping each to its runtime root by canonicalising and checking the `host/` marker for both layouts.
- C#: on Windows the off-PATH fallback produced nothing at all rather than merely less. No machine-wide install was probed, despite `dotnet_root_from_binary` already reasoning about `C:\Program Files\dotnet`; `windows_dotnet_roots` now honours `ProgramFiles` and `ProgramFiles(x86)` first so a non-default system drive or a 32-bit install resolves, with the literals as the fallback. The per-user candidate never resolved either, because every `~/.dotnet` lookup keyed on `HOME` and Windows sets `USERPROFILE`; `user_home` reads `HOME` then `USERPROFILE`.
- scip-reader: `document_text` did `project_root.strip_prefix("file://")`, which turns `file:///C:/work/repo` into `/C:/work/repo`, not a valid Windows drive path, and never decoded percent escapes, so a repo under a path with a space or a non-ASCII name failed too. Both failed silently: every column became `None` with no log line, on the platform whose JVM and .NET Phase B shipped in 0.4.2. `file_uri_to_path` handles the drive form, percent escapes and the empty and localhost authorities, and `source_root` falls back to the wrapper's own repo root when `project_root` is absent, relative or unparsable. A source that cannot be read logs at debug, so a zero-column run is diagnosable.
- scip-reader: a test or spec suffix now requires a word boundary, so `latest.rb` and `contest.go` stop reading as test sources and cannot raise a false test-blind diagnostic.
- Swift, Scala, Dart: the column points at the referenced identifier rather than the start of the expression. The Swift emitter took `colOf(node)` on the whole call expression, so for `svc.charge()` the column was the start of `svc`, and the daemon feeds this straight to the editor's definition provider as the precise identifier position, so it would have resolved the receiver variable or the type on every explicit-receiver call. Dart's `InstanceCreationExpression` passed `node.offset`, the `new` or `const` keyword when one is written, rather than the constructor name's own offset. Scala reads the source for its column under `sbt_root` rather than the repo root, since SemanticDB uris are relative to sbt's sourceroot and `find_sbt_root` allows a nested `build.sbt`, where every column would otherwise be `None`.
- PHP: three defects in the artifact handling, each of which produced a silent zero-node index or lost a file in the checkout. `clear_leftover_artifact` deleted whatever sat at scip-php's hardcoded output path before a run, but on a sandboxed Linux run the host pre-creates that path as a zero-byte stub (bwrap needs its bind source to exist), so the guard called `remove_file`, took EROFS from the read-only repo root and aborted the whole run, and PHP Phase B returned nothing on every sandboxed Linux run. The contents are now copied into scratch and put back, the only operation every platform's policy actually grants, and nothing is created, renamed or unlinked in the repo root on any path. `RepoArtifact::drop` opened and truncated in place when a restore was owed and never unlinked, because on Windows the sidecar holds DELETE on the file but not FILE_ADD_FILE on the read-only root, so the delete succeeded and the recreate could not, destroying the user's file. A leaked `index.scip` on a failure path also tripped the next run's guard and wedged PHP Phase B permanently with a silent zero-node result; a drop guard now removes it on all paths.
- C, C++, Ruby, PHP: the invoke scratch directory is validated before it is trusted. All four checked only that `req.scratch` was non-empty, which it never is, while the plugin host filled it with the host path of its tempdir and bwrap maps that path nowhere inside the namespace. On a sandboxed Linux run they wrote into a directory that does not exist in their own namespace, so scip-clang and scip-ruby produced no index and the language reported zero nodes with no error. travsr now sends a path the sidecar can open, but sidecars ship through npm independently of the binary, so a new sidecar talking to an older host is an ordinary deployment shape. Each now uses the field only when it names a directory this process can see, falls back to a tempdir (which the sandbox's own `TMPDIR` points at the granted scratch mount) and logs the rejected path.
- Java: a build command given to scip-java replaces its default argv rather than extending it, so the configured Maven `test-compile` silently dropped `clean` and a warm repo indexed to nothing.
- Java: `maven clean` is allowed to fail inside the sandbox (`-Dmaven.clean.failOnError=false`). The host grants `target/` as a bind over a read-only repo root, so maven-clean-plugin can delete everything inside `target/` but not the directory itself, and by default that single failure is fatal. Clearing the contents is all `clean` was needed for here, because scip-java passes `-Dmaven.compiler.useIncrementalCompilation=false` and clearing the classes is what makes every source stale again.
- Kotlin: a failed server read keeps the nodes collected so far instead of discarding all of them, and the progress deadline is clamped to the host budget. Only responses and `$/progress` are parked, so the one `publishDiagnostics` per opened document no longer accumulates in a queue that every request scans in full.
- Dart: `DART_SDK` is set on the emitter child. The emitter is AOT-compiled, so its own SDK auto-detection resolves relative to its install directory; `emit.dart` reads `DART_SDK` and passes it to the analyzer as `sdkPath`. The CI smoke test now passes it too, so it exercises the real invocation rather than dying with `PathNotFoundException`.
- Swift, Dart: stderr is drained concurrently rather than after the poll loop, and the `--version` probe is bounded by a timeout.

## [0.4.2] - 2026-08-22

Windows Phase B for the JVM and .NET wrappers, which shipped binaries in v0.4.0 but produced nothing when run, plus graph noise-node cleanup. No API or protocol changes (#22).

### Fixed

- Kotlin: `travsr-lang-kotlin` produced zero symbols and zero edges on every Windows machine. Two bugs stacked. `kls_binary()` probed the bare `kotlin-language-server` name with `Path::exists()` and `Command::new`, neither of which resolves the `.cmd` launcher `travsr lang install kotlin` writes on Windows (a bare `Command::new` auto-resolves only `.exe`), so lookup always returned `None` and `run_kls()` failed silently before spawning the server. With the binary found, `path_to_uri` still built `file://` URIs with `format!("file://{}", path.display())`, which on Windows yields `file://D:\repo\Foo.kt`: backslashes and no leading slash before the drive letter, illegal in a URI authority. KLS caught the resulting `URISyntaxException` per call rather than crashing, so the session completed cleanly with nothing in it. Binary lookup now goes through `travsr_core::exec::tool_path` (the shared PATHEXT-aware resolver), and `path_to_uri`/`uri_to_rel` strip the `\\?\` verbatim prefix and normalize symmetrically to `file:///D:/...`.
- Kotlin: `path_to_uri` percent-encodes non-unreserved bytes, so a path containing spaces produces a URI `java.net.URI` accepts instead of throwing per call. `uri_to_rel` case-folds the drive letter so a lowercase drive echoed back by KLS still matches the root, and `percent_decode` decodes into a byte buffer before `from_utf8_lossy` so multi-byte UTF-8 is not mangled and a malformed escape stays literal.
- Kotlin: the managed `~/.travsr/bin` launcher is preferred over PATH on unix as well as Windows, so a stale system-wide KLS cannot shadow the installed version, and the launcher is now checked for the execute bit (`is_runnable_file`) instead of mere existence.
- Java: Phase B on Windows produced zero edges regardless of whether Gradle was installed. The scip-java release travsr ships invokes the build tool by its extensionless name, which a Windows JVM's `ProcessBuilder` cannot run for `.cmd`/`.bat`, so `scip-java index` never drove the build. On Windows the wrapper now drives a Gradle build itself: it extracts scip-java's SemanticDB plugin jars from the launcher (through the JDK's own `jar` tool, since the coursier polyglot layout defeats the Rust `zip` reader's end-of-central-directory scan), runs the repo's `gradlew.bat` with a travsr-generated init script that applies the plugin and redirects build output out of the repo, converts the emitted `.semanticdb` files with `index-semanticdb`, and ingests the result. The unix path is unchanged.
- C#: `travsr-lang-csharp` forwarded the daemon's `\\?\`-prefixed `InvokeRequest::root` straight to scip-dotnet as the project path and `--working-directory`. scip-dotnet builds a `file://` URI from it and `System.Uri` reads the `\\?\` as a UNC authority, aborting the whole index with `UriFormatException` before `dotnet restore` ran. The verbatim prefix is now stripped at the top of `run_scip_dotnet`. `scip_dotnet_binary` and `dotnet_root` also moved to `travsr_core::exec::tool_path`, replacing hand-rolled lookups that never matched a `.exe`; `dotnet_root` requires a real `sdk/` directory and falls back to `~/.dotnet` when the `dotnet` on PATH is a runtime-only host.
- Java, C#, Scala: the wrappers read the child process's piped stdout and stderr only after it exited, so a chatty build filled the OS pipe buffer (64 KiB), the child blocked writing, and the wrapper blocked waiting for it to exit. This surfaced as a multi-minute "slow build" that the daemon watchdog then killed. All three now drain both pipes on dedicated threads while the process runs. The Java driver also drops `--debug`, which filled the buffer in about a second on its own.
- Java, Scala, C#, Kotlin: on timeout the wrappers killed only the direct child, orphaning the Gradle, sbt, dotnet/msbuild and KLS JVM grandchildren while the drain threads waited on them. All four now kill the whole process tree (`taskkill /F /T` on Windows).
- Java, Scala, C#, Kotlin: `strip_windows_verbatim_prefix` degraded a `\\?\UNC\server\share\...` path into a relative one by removing the leading backslashes. It now keeps them and returns `Cow`, avoiding an allocation on the common no-prefix path. Tests that asserted the degraded form were corrected.
- Scala: parameter descriptors (`com/demo/Greeter#greet().(name)`) and anonymous locals (`localN`) leaked into the graph as raw nodes with their own ref and call edges. The scip-reader path already filtered both; the SemanticDB reader did not, so a Scala parameter showed up as a bare `(name)` node where every other language hid it. `is_local_symbol` and `is_parameter_descriptor` join the existing stdlib check in `is_noise_symbol`, applied everywhere `build_edges` previously checked `is_stdlib_symbol`.
- scip-reader: SCIP `Parameter` descriptors (terminal `(name)`) are dropped from both the definition and the reference pass, the same treatment `local N` already got. scip-dotnet emits parameters as definitions where scip-go and scip-java do not, so they surfaced as raw `scip:...(name)` graph nodes.

### Changed

- Scala: removed debug scaffolding from the per-invoke path, a DNS and TCP probe to `repo1.maven.org` and an unbounded dump of the environment, PATH and build stdout to `~/.sbt/scala-wrapper-debug.log`.
- Removed every em-dash from the repository (134 across 28 files: Rust doc comments and inline comments, the Swift and Dart emitter sources, the objc fixtures, `npm/postinstall.js`, the CI and release workflows, and the rpath guard script), per the Travsr-com house style. Each was rewritten in place with a colon, comma, period or parentheses rather than mechanically substituted. Most are comments, but the wrapper "tool not found" messages are user-facing, so their wording changes slightly (for example, `scip-go not found - install with: ...` now reads `scip-go not found. Install with: ...`). No behavior change.
- Java: dropped the isolation-era Gradle workarounds (`--project-dir`, `--no-watch-fs`, the `GRADLE_USER_HOME` temp redirect and the jvmargs tmpdir override) and the `dbg_log` scratch logging, now that this path runs with the user's own privileges. The driver is trimmed to the minimal recipe run from the repo root.

## [0.4.1] - 2026-08-16

### Fixed

- Ruby: `travsr-lang-ruby` now passes the checkout directory (`.`) as scip-ruby's positional input. Without it scip-ruby exited 1 ("You must pass either `-e` or at least one folder or ruby file.") and wrote nothing, so every Ruby symbol carried only a `defines/binding` edge and `find_references` returned pending (travsr-lang#17).
- Objective-C: `travsr-lang-objectivec` loads libclang dynamically at runtime (clang-sys `runtime` feature) instead of link-binding it. The release binary previously baked the build host's Xcode path into `LC_RPATH`, so dyld aborted the process before `main()` on any machine without that exact path, which also stalled the whole repo's Phase B on the host side. libclang is now resolved against the active toolchain (`LIBCLANG_PATH`, then `xcrun`, then well-known dirs) and a missing libclang is a catchable error, not a crash (travsr-lang#17).
- Java: `travsr-lang-scip-reader` now decodes scip-java 0.13.1's structured `Range` sub-messages (proto fields 8 to 11), not just the classic packed int32 arrays at fields 1 and 7. Those ranges previously came back empty, every occurrence fell back to line 1, and the range guard dropped it, so Java Phase B produced definitions but zero call edges. The decoder handles both oneof arms (single-line and multi-line) and fills proto3's zero-elided fields instead of truncating on them. Ruby, Go, Python and TypeScript use the classic packed encoding and were unaffected (#724).

### Added

- A release check (`.github/scripts/check-no-buildhost-rpaths.sh`) that fails the build if the objc emitter regresses to a link-time libclang dependency or a build-host absolute rpath (travsr-lang#17).

## [0.4.0] - 2026-08-15

### Added

- Windows (`x86_64-pc-windows-msvc`) release builds for every wrapper binary, published as `travsr-lang-<lang>-x86_64-pc-windows-msvc.exe` alongside a matching `.exe.sha256` (travsr#588). No previous tag had shipped a Windows asset. `travsr-lang-objectivec` stays macOS-only, since it links libclang and shells out to `xcrun`.

  This release is what makes the assets exist. The CLI half landed in Travsr-com/travsr#704, which already builds the `.exe` name correctly but does not yet claim Windows as available, because no published tag carried the assets when it merged. Adding `x86_64-pc-windows-msvc` to its `WRAPPER_RELEASE_TARGETS` is the remaining step, and this tag is its prerequisite.
- `npm/postinstall.js` resolves `win32`/`x64` to `x86_64-pc-windows-msvc` and handles the `.exe` suffix on both the downloaded asset and the file it writes. Without it `npm i @travsr-plugin/<lang>` on Windows declined to fetch a binary the release now contains.
- A Windows CI job that builds all twelve wrappers, runs the test suite, and rehearses the release packaging, so a Windows-only compile break or an asset-naming mistake surfaces on the PR rather than midway through publishing a tag.
- Dart: references from type positions and typedefs. The emitter previously recorded references only from method invocations, instance creations and prefixed identifiers, so a type used as a parameter, a generic argument, or in an `extends`/`implements`/`with`/`on` clause produced none.
- Objective-C: C functions now carry the `.()` function suffix so they unify with Phase A `fn:<name>` nodes instead of surviving as duplicate term nodes, and clang-synthesized property getters and setters are skipped (#596).

### Changed

- **Licence changed from MIT to Apache-2.0.** The repository previously declared MIT in its manifests but shipped no `LICENSE` file at all; this release adds the licence text and standardises every crate and npm package on Apache-2.0.
- Swift and Objective-C emit `RefCall` edges for bare member accesses, not just calls, and Swift constructor calls target the type symbol directly rather than a synthetic `.init` member, so `find_references` resolves by class name (#449).
- Kotlin, Swift and Scala no longer emit a redundant structural `RefCall` edge alongside the `ScipRef` for the same reference. The daemon wrote both, producing a spurious file-to-callee edge next to the correctly re-homed one.
- The wrapper binary list and the release packaging rules moved into `.github/wrapper-bins.txt` and `.github/scripts/package-wrappers.sh`, shared by the release workflow and the Windows CI job. They were previously three hand-maintained copies of the same list, where a name added to one and missed in another would silently ship a release the installer expects and cannot find.

### Fixed

- `ScipRef.is_call` is now set at all four construction sites, matching the field travsr-core made required in #650. Without it `cargo check --workspace` failed to build.

## [0.3.0] - 2026-07-12

### Added

- Occurrence emission (`ScipRef` records) across the Scala, Kotlin, Swift, and Dart Phase B plugins and the shared scip-reader. This powers all-language `find_references` and `find_pattern` in the travsr CLI (#299).

### Fixed

- Objective-C plugin: bake the libclang RPATH into the binary via `build.rs` so it resolves libclang at runtime instead of relying on a stale or absent library path.

## [0.2.1] - 2026-06-11

### Fixed

- Go plugin: changed `scip-go` invocation from `scip-go --output <f> <root>` to `scip-go index --output <f> ./...` (cwd=root). The old form loaded only the root package, producing zero semantic edges on multi-package repos. `./...` is the standard Go recursive package pattern.
- Java plugin: removed spurious positional `<root>` argument from `scip-java index --output <f>`. scip-java uses cwd for project discovery; the extra argument caused an error on unknown trailing argument.

## [0.2.0] - 2026-06-10

### Added

- Swift Phase B plugin: structural analysis via the bundled `swift-index-emitter` (SwiftSyntax). Produces call edges, type references, and inheritance edges. Available as `@travsr-plugin/swift`.
- Dart Phase B plugin: semantic analysis via the bundled `dart-scip-emitter`. Available as `@travsr-plugin/dart`. The npm package installs share files to `~/.travsr/share/` and runs `dart pub get` on first install.
- Scala Phase B plugin: semantic edges via SemanticDB and `sbt compile`. Available as `@travsr-plugin/scala`.
- C# Phase B plugin: semantic edges via `scip-dotnet`. Available as `@travsr-plugin/csharp`.
- Kotlin Phase B plugin: semantic edges via `kotlin-language-server` LSP client. Available as `@travsr-plugin/kotlin`.
- One-command install for Swift and Dart: `travsr lang install swift` and `travsr lang install dart` now resolve the emitter path automatically.

### Fixed

- PATH fallback for Phase B binary resolution: all 7 SCIP-based plugins (C, C++, Go, Java, PHP, Python, Ruby) now correctly probe the system PATH when the binary is not found at the default install location.
- Scala: `sbt` binary PATH fallback aligned with the same probe logic.
- Python plugin: improved install hint when `scip-python` is not found.
- PATH probe exit code handling: non-zero exit from a probe no longer causes a spurious error.

## [0.1.0] - 2026-05-31

### Added

**Language crates**: SCIP-based semantic analysis binaries for ten languages:

| Binary | Language |
|---|---|
| `travsr-lang-c` | C |
| `travsr-lang-cpp` | C++ |
| `travsr-lang-csharp` | C# |
| `travsr-lang-go` | Go |
| `travsr-lang-java` | Java |
| `travsr-lang-kotlin` | Kotlin |
| `travsr-lang-php` | PHP |
| `travsr-lang-python` | Python |
| `travsr-lang-ruby` | Ruby |
| `travsr-lang-scala` | Scala |

**SCIP binary ingestion**: `travsr-lang-scip-reader` crate reads `.scip` protobuf output and threads the symbol corpus into the Travsr indexing pipeline.

**npm distribution**: `@travsr-plugin/<lang>` packages for all ten languages. Each package downloads the correct pre-built binary for the host platform/arch on `npm install` via a shared `postinstall.js` script.

**GitHub Actions release workflow**: push a `v*.*.*` tag to:
1. Create a GitHub Release with auto-generated notes.
2. Build and upload binaries for `x86_64-apple-darwin`, `aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`, and `aarch64-unknown-linux-gnu`.
3. Publish all `@travsr-plugin/*` packages to npm.

### Changed

- Migrated from local path dependencies to published `travsr-plugin-sdk` and `travsr-core` crates.
- Removed redundant `travsr-lang-rust`, `travsr-lang-typescript`, and `travsr-lang-lsif` crates (replaced by SCIP-native pipeline).
- `travsr-lang-php`: pass `--output` flag explicitly to `scip-php`.
